# Explain code

AI must be enabled in settings (`"disable_ai": false`). An explicit AI disable setting is respected.

Select a block in the editor, or place the caret on a line, then use the context menu action **Explain with Claude** or **Explain with Codex**. The same actions are available in the command palette.

The selected provider opens a dedicated explanation conversation in the agent panel. The request includes an editor snapshot with the file path, language, selected line numbers, selected text, enclosing symbol when the language grammar supplies one, and the beginning of the file. Unsaved edits are included. For multiple selections, only the first range is used.

The first response is requested in plain language, at most 150 words, covering syntax and purpose in context. **Explain more** requests a walkthrough, examples and edge cases in the same conversation. The normal message composer supports follow up questions. Explanations are generated by the provider and can be incorrect; the prompt asks it to distinguish evidence from assumptions.

## Accounts and setup

Use **Install agents** to open the agent registry if the provider is unavailable. **Connect account** uses the connected provider's existing authentication flow. **Agent settings** opens Hulder's existing configuration surface. Hulder does not collect subscription passwords or implement a separate credential store for this feature. Account eligibility, usage limits and available authentication methods are controlled by the provider and adapter.

The explanation action sends the supplied source snapshot to the selected provider. It requests explanation only, with no tools, commands or file edits. This instruction is not a separate security sandbox; the existing agent permission controls still apply. Starting another explanation creates a new conversation, so unrelated code explanations do not silently share context.

## Context limits

Selected code is capped at 16000 characters, enclosing code at 24000, and file context at 32000. Truncated content is explicitly marked. The selected code is preserved separately so selections late in a large file are still included. The snapshot does not automatically resolve every import or related file.

Explain more controls are associated with explanation conversations and restored with the workspace after restarting Hulder. Existing conversation history and provider sign in are managed by the agent panel.

Provider authentication references: [Codex authentication](https://learn.chatgpt.com/docs/auth) and [Claude Code authentication](https://code.claude.com/docs/en/authentication).

## Markdown and context tools

**Export Markdown** opens the current conversation as an editor document. Use Save As to choose a destination. It includes the source snapshot sent to the provider, your follow up messages and recorded responses.

**Save context folder** writes one Markdown file per conversation under Hulder's application data directory in `context/`, and reveals the file in Finder. It refreshes changed conversations every three seconds while this Hulder window remains open. **Stop context updates** requests a final snapshot before stopping and leaves the saved file in place. Removing the conversation cancels its mirror. Restarting Hulder does not automatically resume mirroring. The file is an atomic snapshot, so readers do not see a partially written update. Saved context may contain private code and conversation text. Keep it outside public repositories and review it before sharing.

## Feedback Graph

Feedback Graph can stay a separate service. Start it using its own setup instructions, then select **Connect Feedback Graph**. This adds the local MCP endpoint at `http://127.0.0.1:8787/mcp` without replacing an existing configuration. Start a new agent conversation after connecting. Provider tool permissions still apply. The concise explanation request deliberately asks the agent not to call tools; ask a follow up explicitly requesting Feedback Graph context when you want its project lessons.

If your instance uses a different port or authentication, edit its `context_servers` entry in Agent settings. This build's built in HTTP transport permits only the default local endpoint; external ACP agents may support other configured endpoints using their own transport. Credentials belong in your local settings, never in exported examples.

Feedback Graph's current importer accepts its structured knowledge export format, not arbitrary Markdown conversations. The context folder is available for file based tools; it does not automatically import lessons into Feedback Graph or approve them. Its MCP tools and existing transcript ingestion remain the supported integration paths.

## Context history

Open the Agent Panel using its status bar button, then select **Context history**. The same action is available in the command palette. The view lists saved context snapshots across projects, newest first, with 50 conversations per page. Select a row to read the Markdown in an independently scrollable pane. **Refresh** reloads the list; **Open folder** reveals the context directory. Reopening the view reuses its tab instead of creating duplicates.

The history contains conversations explicitly saved with **Save context folder**, including regular agent conversations. It is not an automatic archive of every unsaved chat. Files survive restarts, but continuous export must be enabled again for an active conversation. Regular `.md` files are listed; symlinks and other file types are excluded. Files over 4 MiB have a bounded preview with a notice; open the context folder to read the complete file. An unreadable file remains visible with an error and does not hide other conversations.
