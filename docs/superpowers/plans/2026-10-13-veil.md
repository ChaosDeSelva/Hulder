# Veil Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A privacy screen for Hulder. One keystroke turns every drawn glyph in every window into Elder Futhark, swallows input behind a full-window overlay, and only the passkey brings the text back.

**Architecture:** gpui grows one hook, `Window::set_text_veil`, that the window's `LineLayoutCache` consults at the single point where a line is handed to the platform text system. The veil maps text char-for-char, so font-run byte lengths are rescaled on the way in and glyph indices are mapped back to the original byte offsets on the way out; every consumer of `LineLayout` keeps working in original-text coordinates. A new crate `veil` owns the transliteration table (`runes.rs`), the passkey store (`store.rs`), the global `Veil` entity with its actions, overlay and keystroke interceptor (`veil.rs`), and the status bar button (`status.rs`). `workspace` gains a tiny additive `set_overlay` slot rendered last in the root element. `zed` wires init, the status item, the keymap and the namespace test.

**Tech Stack:** Rust, gpui (entities, `intercept_keystrokes`, `observe_new`, animations), `editor::Editor::single_line`, `sha2` + `rand` + `hex` for the store (no `argon2`/`scrypt` in the workspace), `serde_json` for `veil.json`.

**Spec:** `docs/superpowers/specs/2026-10-13-hulder-design.md`, section 16.

## Global Constraints

- The veil callback maps one char to exactly one char. `x` maps to `ᚲ`, not `ᚲᛊ`, so the gpui remap stays a per-char bijection. gpui still tolerates a mismatch (it clamps), but the rune table never produces one.
- The hook costs one `RwLock` read per platform layout when `None`. No allocation, no copy.
- The veil is app-wide, not per window: gpui's `TextVeilState` global holds a `TextVeilSource` (the Veil's shared state), and every window consults it at the start of each draw. There is no `Window::set_text_veil`; the window only exposes `text_veil()`. A window opened while locked is veiled on its first frame, and nothing but `Veil::unlock` (after a verified passkey) can lift it.
- Cache keys are the original text, so a change of veil generation clears both frames of the line layout cache; otherwise an unveiled layout could be served for a veiled frame and vice versa.
- Passkey hashing: neither `argon2` nor `scrypt` is in the workspace, but `pbkdf2` 0.12 is in the lockfile, so the store uses PBKDF2-HMAC-SHA256 with 600 000 rounds and a 16-byte random salt. The scheme and round count are written into `veil.json` so a later migration to Argon2id can detect the old format. The compare is constant time, the typed passkey lives in a `Zeroizing<String>`, and the file is created with mode 0600.
- The key itself is never stored and never logged.
- Rate limiting is persisted: `veil.json` carries `failed_attempts` and `locked_until` (unix seconds). `verify` refuses to compare while `now < locked_until`. The lockout starts at 10 s after three failures and doubles per failure up to 5 minutes; a successful unlock resets both.
- While locked, two gpui interceptors run before anything else. `intercept_keystrokes` drops every keystroke with `cmd`, `ctrl`, `alt` or `fn`, except `cmd-v`, `cmd-a` and `cmd-backspace`. `intercept_actions` (added to gpui for this) drops every action that is not `menu::Confirm`, `menu::Cancel`, `veil::Toggle` or one of the unlock editor's own editing actions, whatever dispatched it: key binding, menu, command palette, mouse-driven button or `window.dispatch_action`. Both read an `Arc<SharedState>` rather than the entity, since they can fire while the entity is mid-update.
- `MultiWorkspace::close_window` returns early while a workspace overlay is installed, which covers the window close button (it bypasses action dispatch).
- `veil::Toggle` while locked only refocuses the unlock field; `SetPasskey` while locked does nothing, and when a passkey exists it asks for the current one first.
- `locked` is persisted in `veil.json`: set before the overlays go up, cleared only after a verified unlock. `init_with_store` locks at startup when the record says so, before any workspace exists, so restored windows get their overlay through `observe_new`.
- Both passkey editors are masked (`Editor::set_masked`), since the rune veil is off while a passkey is being set, and are cleared on confirm and cancel. `Editor::is_masked` was added so tests can assert it.
- Follow repo CLAUDE.md: no `unwrap()` outside tests, no `let _ =`, no `mod.rs`, `./script/clippy` not `cargo clippy`. Keep README's `> [!IMPORTANT]` marker in place.
- `veil.auto_after_minutes` depends on app-wide idle detection, which gpui does not have (`last_input_was_keyboard` is a modality flag, not a timestamp). The setting is skipped and reported.

## Review Focus

1. Layout coordinates: with the veil on, `LineLayout.len` and every `ShapedGlyph.index` must be byte offsets into the *original* text, or editor cursors, decoration runs and wrap boundaries drift or panic. Test in Task 1 (`apply_text_veil` and remap unit tests, `shape_line("abc")` through a recording platform).
2. Lock re-entrancy: `veil::Toggle` is handled inside a `Workspace` update, and locking updates every workspace. Lock and unlock run through `cx.defer`. Test in Task 4 (gpui test: toggle from a workspace, run until parked, assert overlay on both windows).
3. Focus stickiness: the overlay editor must regain focus if anything blurs it while locked, otherwise typed keys fall through to the editor behind. Test in Task 4 (manual, listed).
4. Rate limiting: after three failures each attempt waits 10 s before being verified; a wrong key during the wait is not verified at all. Test in Task 4 (`attempt_delay` pure function).
5. Store file permissions: `veil.json` is 0600 on unix even when it already existed. Test in Task 3 (metadata mode check).
