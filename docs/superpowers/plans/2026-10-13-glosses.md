# Glosses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Marginalia for code. A gloss is a Markdown note attached to a file or to a line range, stored as plain text under `.hulder/glosses/`, re-anchored by text when the file changes, shown as a gutter mark in the editor and as context in the Grove's hover popover.

**Architecture:** One new crate `glosses` holds the pure file model (`model.rs`: parse, serialize, re-anchoring, path safety) and a `GlossStore` global entity (`store.rs`: async load/save through `fs::Fs`, cached per worktree, invalidated on `project::Event::WorktreeUpdatedEntries`). The `editor` crate depends on `glosses` for the gutter mark, the click popover (a sibling of `InfoPopover` inside `HoverState`), and the `glosses::AddGloss` action with its single-line prompt modal. `project_panel` depends on `glosses` for the file-row hover popover. `glosses` depends on `project` but never on `editor`, so there is no cycle. The `zed` crate wires `glosses::init` next to `herd_panel::init`.

**Tech Stack:** Rust, gpui (entities, globals, `cx.spawn`, `cx.background_spawn`), `fs::Fs` (`FakeFs` in tests), `chrono` for RFC 3339 timestamps, `markdown::Markdown` for popover rendering, `workspace::ModalView` for the prompt.

**Spec:** `docs/superpowers/specs/2026-10-13-hulder-design.md`, sections 14 (Glosses), 8.2 (tree hover popover), 11 (Saga layout).

## Global Constraints

- File format (one file per source file at `.hulder/glosses/<relative path>.md`):
  ```
  ## Gloss
  line: 42-48
  anchor: let total = items.iter().sum();
  created: 2026-10-13T09:30:00Z
  author: claude

  Markdown body until the next `## Gloss`.
  ```
  `line:` and `author:` are optional. `line:` is 1-based inclusive (`42` alone means `42-42`). A gloss without `line:` is a file-level gloss. `anchor:` is the trimmed text of the first anchored line (empty for file-level glosses). `created:` is RFC 3339 UTC, serialized as `YYYY-MM-DDTHH:MM:SSZ`.
- Re-anchoring searches ±200 lines around the recorded start line, nearest offset first: exact trimmed match, then whitespace-insensitive match. Not found means `Detached`; a detached gloss is never deleted.
- Path safety: the relative path is normalized (`.` components dropped), rejects `..` components and absolute paths; the on-disk gloss path is checked with `symlink_metadata` (via `Fs::metadata(..).is_symlink`) before any read or write and refused when it is a symlink.
- `crates/saga` and `crates/bifrost` are built by other agents and must not be created here. `GlossStore::all_for_worktree` is the public API they will call.
- Follow repo CLAUDE.md: no `unwrap()` outside tests, no `let _ =` on fallible calls, no `mod.rs`, `[lib] path = "src/glosses.rs"`, `./script/clippy` not `cargo clippy`.
- Keep README's `> [!IMPORTANT]` marker in place.
- Build with `export CARGO_TARGET_DIR=/Users/jlashley/Code/cotzed/target`; the target directory is shared with other agents.

## Review Focus

1. Path traversal: `.hulder/glosses/../../etc/passwd.md` or an absolute path must be rejected before any filesystem call. Test in Task 2 (`normalize_relative_path` rejects `..`, `/abs`, empty; `gloss_file_path` stays under the root).
2. Symlinked gloss file: a `.hulder/glosses/x.md` that is a symlink must be refused for both load and save, with an error, not followed. Test in Task 3 with `FakeFs::create_symlink`.
3. Re-anchoring must prefer the nearest match, not the first in file order, and must fall back to whitespace-insensitive matching only when no exact match exists. Test in Task 2.
4. Cache invalidation: editing `.hulder/glosses/<p>.md` externally must drop the cached entry for `<p>` and notify observers. Test in Task 3 by emitting a synthetic `WorktreeUpdatedEntries` through a real `Project` on `FakeFs`.
5. Editors in multi-buffers and buffers without a project file must show no marks and never panic. Covered by `active_gloss_rows` returning early when `as_singleton()` or `project::File::from_dyn` is `None`.
