# The Kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tabbed strip at the bottom of the Grove (the project panel) that lists what an agent will use in this project: Skills, Agents (file definitions plus live herdr agents), MCP servers (with a running dot and one-click add for Bifröst and the panda), and Rules (a checklist of the files an agent reads, with "missing" hints and a Create AGENTS.md button).

**Architecture:** One new crate `kit`. `scan.rs` is pure: given relative paths from a worktree snapshot plus a reader closure, it produces `KitScan { skills, agents, mcp, rules }`; it is driven by a temp dir in tests and by the worktree snapshot and `fs` in the app. `kit.rs` holds the `Kit` gpui view (tabs, rows, actions). The project panel owns the layout (collapsed flag, height, resize handle, header chevron) and persists it in the kvp store next to the Grove lists. Live herdr agents come from `herdr::HerdState`, reached through a `kit::init`-installed global so tests that never call `init` get no live rows instead of a panic.

**Tech Stack:** Rust, gpui (`cx.background_spawn`, `on_drag`/`on_drag_move`), `ui::{ListItem, Button, Icon, Indicator}`, `db::kvp` for persistence, `sysinfo` (already a workspace dependency) for the MCP running state, `lightpanda::mcp::share_with_agents` for the panda entry.

**Spec:** `docs/superpowers/specs/2026-10-13-hulder-design.md`, section 15 (section 8 for the Grove, section 5 for the Herd).

## Global Constraints

- Follow repo CLAUDE.md: no `unwrap()` outside tests, no `let _ =` on fallible calls, no `mod.rs`, `./script/clippy` not `cargo clippy`, crate root named after the crate (`src/kit.rs`).
- Do not modify `crates/herdr`, `crates/herd_panel`, `crates/editor`, `crates/browser`, `crates/lightpanda` (read-only use; the panda button calls the existing `share_with_agents`).
- No new action namespace: the toggle is `project_panel::ToggleKit` so the `zed.rs` namespace list is untouched.
- All four tabs are file listings from the worktree snapshot plus `~/.claude.json`; parsing is limited to front matter and JSON.
- Refresh is debounced 300 ms and scans in a background task.
- No network.

## Review Focus

1. `HerdState::global` panics when `herdr::state::init` was never called (project panel tests). The Kit must resolve herdr state through `cx.try_global` on a kit-owned global. Test: `live_agents_for_root` is tested on plain `WorkspaceRow` data; panel tests construct the panel without `kit::init`.
2. `.mcp.json` must never lose keys when the hulder entry is added. Test in Task 1 (`merge_mcp_server` keeps sibling servers and unrelated top-level keys, and errors on invalid JSON instead of replacing the file).
3. Front matter parsing must survive missing or malformed front matter (no `---`, unterminated block, values with colons). Test in Task 1.
4. Resize must clamp: the Kit can never cover the whole panel or shrink below its header. Test: `clamp_kit_height` pure function in project panel.
5. The scan runs in the background; the view must drop stale results when a newer scan started (generation counter). Test: `Kit::apply_scan` ignores an older generation.

## Known Limitations (to note in the report)

- `crates/saga` does not exist on this branch, so "Create AGENTS.md" writes a short generic template.
- Files under a gitignored `.claude/` only appear once the worktree has scanned that directory (Zed loads ignored directories lazily).
- The MCP running dot matches process command names (file stem of `command` against each live process's name / argv[0]); it cannot tell which project started the server.
