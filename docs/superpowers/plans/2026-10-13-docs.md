# Documents for Agent Work Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hulder reads the documents agents produce and consume without leaving the editor: a native PDF tab, Markdown previews whose relative and `[[wiki]]` links open files in Hulder, a one-key "send this selection to the agent I am looking at", and SVG export of rendered mermaid diagrams.

**Architecture:** One new crate `pdf_viewer` registers a workspace `ProjectItem` for `.pdf` exactly like `image_viewer`; rasterization is CoreGraphics (`CGPDFDocument` drawn into a BGRA bitmap context, hand-declared FFI because `core-graphics` 0.24 exposes no PDF API) and text extraction is PDFKit through `objc` message sends, both `cfg(target_os = "macos")`. The Markdown parser (`crates/markdown`) learns `[[wiki links]]` as a parse option so source offsets stay intact; `markdown_preview` resolves them against the file's directory and worktree root. `herd_panel::SendSelection` reads the active editor selection and the `HerdView`'s shown agent terminal and calls herdr `agent.send`. Mermaid export adds a `context_menu_mermaid` capture to `crates/markdown` and two entries in the preview's existing right-click menu.

**Tech Stack:** Rust 1.98, gpui (`Item`, `ProjectItem`, `RenderImage` BGRA premultiplied frames), `core-graphics` 0.24 + `core-foundation` 0.10 + `objc` 0.2 (already in the workspace), `image` for frames, pulldown-cmark text post-processing in `crates/markdown/src/parser.rs`, `herdr::HerdrClient::request`, `cx.prompt_for_new_path`.

**Spec:** `docs/superpowers/specs/2026-10-13-hulder-design.md`, section 10.

## Global Constraints

- No new crates.io dependencies; everything used is already a workspace dependency.
- No network. PDF rendering and text extraction are local system frameworks.
- Follow repo CLAUDE.md: no `unwrap()` outside tests, no `let _ =` on fallible calls, no `mod.rs`, `./script/clippy` not `cargo clippy`.
- Integration edits to `crates/zed/src/main.rs`, `app_menus.rs`, `assets/keymaps/default-macos.json`, `Cargo.toml` are additive one-liners.
- Non-macOS builds must still compile: `pdf_viewer` becomes a placeholder item there.
- Keep README's `> [!IMPORTANT]` marker in place.

## Review Focus

1. PDF rasterization must never block the UI thread per frame: pages render in `cx.background_spawn`, cached per `(page, zoom)`, only for pages near the viewport. Test in Task 1 (cache key math, fit-width zoom math) and the CoreGraphics integration test (page 1 of a generated PDF yields a non-empty bitmap).
2. PDFKit text can be empty for scanned PDFs: `OpenAsMarkdown` must still produce one `## Page N` heading per page. Test in Task 1 (`pages_to_markdown` with an empty page).
3. Wiki link detection must not change source offsets, or editor-to-preview scroll sync breaks. The parser emits a `Link` with `SubstitutedText` over the original `[[...]]` range. Test in Task 2 (parser events carry the original range).
4. `SendSelection` with no Herd view, no shown agent, or an empty selection must toast and send nothing. Test in Task 3 (`shown_agent_terminal_id` on `active_key` values, `selection_to_send` on empty text).
5. Mermaid export must render from the diagram source with the current theme, not a stale cache. Task 4 reuses `markdown::render_mermaid_svg`.
